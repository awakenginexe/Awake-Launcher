# Native Core corresponding source and redistribution

The helper is GPL-3.0-only. Distribute the complete helper directory and its matching `awake-core-source-<commit>.zip`, with both SHA-256 files, alongside the Manager installer at the same download location. Retain `COPYING.md`, `licenses/`, `REDISTRIBUTION.md`, `SOURCE.json` and `SHA256SUMS` in the installed helper directory. Do not substitute GitHub's automatic repository ZIP: it omits dependency sources and the vcpkg submodule.

`SOURCE.json` identifies the executable's source commit and corresponding-source archive SHA-256. The source ZIP contains the tracked application tree (`awake-source.tar`), full vcpkg scripts/ports (`vcpkg-source.tar`), exact selected registry ports and patches (`ports/`), static dependency sources and Qt/vcpkg-tool source archives (`dependencies/`), triplet, build metadata, dependency references and checksums. No Launcher release, Manager release, signing, or reproducible-build guarantee is implied. A later documentation/artifact commit does not change the executable's source pin.

## Build

Use Windows x64, Visual Studio 2022 C++ tools/Windows SDK, CMake 3.25+, Ninja, Python 3.11+ and Git. The recorded helper used MSVC 19.44, Release, C++23 and dynamically linked Qt Core/Network 6.11.2. Microsoft compiler/SDK/runtime source is not bundled; these are generally available system/toolchain components. Runtime redistribution is governed by the licensed Visual Studio REDIST list and terms: [Microsoft redistribution documentation](https://learn.microsoft.com/cpp/windows/redistributing-visual-cpp-files).

1. Verify and extract the source ZIP; verify its `SHA256SUMS`. Extract `awake-source.tar` into `awake/` and `vcpkg-source.tar` into `vcpkg/`. The standalone helper does not use libnbtplusplus or other Launcher-only submodules.
2. Bootstrap vcpkg (`vcpkg/bootstrap-vcpkg.bat`). Its recorded tool sources are included at the exact `vcpkgTool.commit` in `source-dependencies.json`; the tool can alternatively be built from that archive using its upstream build instructions. Copy `dependencies/*` into `vcpkg/downloads/`. From the bundle root, install the included minimal manifest using `vcpkg/vcpkg.exe install --triplet x64-windows --overlay-ports=ports --overlay-triplets=triplets`. Keep all supplied port patches and the static-library/dynamic-CRT triplet. Build tools may obtain their standard Python/MSYS/CMake components over the network; source references are retained in the supplied vcpkg scripts/ports. No private registry or credentials are required.
3. Obtain Qt's official open-source 6.11.2 MSVC x64 package, or build `dependencies/qtbase-<commit>.tar.gz` using its root `configure.bat`, for example `configure.bat -release -shared -opensource -confirm-license -nomake examples -nomake tests -prefix <qt-install>`, followed by `cmake --build . --parallel 4` and `cmake --install .`. Use the source archive's actual top-level directory. `qt-build/config_qtbase.summary` records the official package configuration; its SBOMs and bundled third-party source/licenses are included. The source commit, rather than a guessed release tag, is authoritative.
4. In an x64 Native Tools shell: `cmake -S awake/native-core -B build-core -G Ninja -DCMAKE_BUILD_TYPE=Release "-DCMAKE_PREFIX_PATH=<qt-install>;<bundle>/vcpkg_installed/x64-windows" -DBUILD_TESTING=ON`, then `cmake --build build-core --parallel 4` and `ctest --test-dir build-core --output-on-failure`. Keep Qt's `bin` on PATH for tests. `AWAKE_CORE_LIVE_TESTS=1` opts into public provider/loader tests.
5. Deploy with `awake/native-core/deploy.ps1 -Executable build-core/awake-core-host.exe -QtBin <qt-install>/bin -DependencyPrefix <bundle>/vcpkg_installed/x64-windows -Destination <new-dir>/core-host/windows-x64`. Then run `awake/native-core/package_release.py --help` and supply the recorded inputs to produce the source ZIP, notices, provenance, manifest and final Windows ZIP together. Use a clean committed checkout when repackaging; do not reuse a previously published hash after changing bytes. To publish a repository delivery, run `awake/native-core/publish_redistribution.py --package-output <output> --destination native-core/redistribution/<commit12>`: it writes the helper ZIP, ordered source parts, LF `.sha256` files, `delivery.json`, `join_source.py`, `README.md` and an outer `SHA256SUMS` over the exact committed bytes (`native-core/redistribution/** -text`).
