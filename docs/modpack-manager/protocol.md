# Awake Modpack Manager integration protocol
Status: experimental protocol 1.0 read-only status/discovery bridge for the clarified Manager status-checking goal. The capability response is authoritative. Reserved write schemas below are a proposal for review, not permission for Manager to write instance files.
Baseline: main `6d91edbe0f168c18a334811d7b08e1b6ce89ef16`.

## Ownership and startup
Launcher owns authentication, Java/GPU settings, launch, native serializers and every live mutation. Manager owns planning and UI. Both address the same physical instance. No export/import, second installation, QWebChannel exposure, shell execution, credential access or third service.
Manager starts Launcher if needed (user decision); normal Launcher startup may show setup/error/auth dialogs. A no-window backend is unsupported. Keep QApplication; do not substitute QCoreApplication.
Each running data profile publishes `integration/v1/endpoint.json` below its effective dataRoot. Resolve Launcher installations and selected profiles on the client; do not guess AppData or silently scan all disks. Windows installed locations use data-location.txt; portable UserData/portable.txt, --dir and AWAKELAUNCHER_DATA_DIR are handled by existing Application startup. Read the descriptor only after choosing that profile. It is a hint: hello must verify installationId/profileId/sessionId. Multiple installations sharing one profile have one coordinator owner; other profiles have distinct endpoints. Descriptor is removed only by its owner. Never unlink a busy socket.

## Transport and trust
Dedicated QLocalServer, UserAccessOption, not LocalPeer. Same OS user is the trust boundary; malware running as that user is outside it. Clients never supply root paths. Unix socket and discovery files must be private to the user; Windows pipe ACL is provided by Qt. The profile directory must be owned by the current user and not writable by other unprivileged users; descriptor files contain non-secret discovery hints and inherit the validated directory ACL. Do not use a shared writable profile for integration.
Each frame: 4-byte unsigned big-endian UTF-8 JSON byte length, then one JSON object. Maximum 1 MiB per request/response; zero length, malformed JSON and oversized lengths close the connection after a structured error where possible. Maximum 8 clients; 30-second idle timeout; one request per connection at a time. No batch JSON arrays. Disconnect never implies cancellation.
Request: `{protocol:{major:1,minor:0},requestId:string,method:string,params:object}`. requestId: 1–64 ASCII letters/digits/_/-, correlation only; reuse across connections allowed. All envelope fields required, unknown fields rejected. method has the same character set plus dots, maximum 64. params has method-specific strict fields. Response echoes requestId (null if invalid), protocol and either `result` or `error:{code,message,retryable}`. A result is a completed read; any future mutation acceptance returns `{operationId,state:"queued",terminal:false}`, never success.
Endpoint publication is Windows-only in this branch; other platforms fail closed until peer-access controls are tested. Descriptor fields: protocol, serverName, pid, installationId, profileId, sessionId. Publish with QSaveFile only after listen succeeds and while holding the profile coordinator lock. Reject links and profiles writable by other unprivileged users; a failed endpoint never prevents ordinary Launcher startup.

First request must be hello with `{versions:[{major,minor}],client:{name,version}}`; choose highest supported minor within major 1. Unsupported majors return UNSUPPORTED_PROTOCOL. Every later request uses negotiated version. Reconnect begins with hello. Servers emit the negotiated minor's payload schema; new payload fields require a newer minor unless extensions are allowed. Minor releases add capabilities, never alter established semantics; unknown capabilities ignored, absent capability is unsupported. Major mismatch fails. Maximum 16 advertised versions. No secrets in responses/events/logs.

## Implemented methods
- `hello` → protocol, installationId, profileId, sessionId, capabilities, limits. capabilities maps method names to booleans; false is a deliberate refusal.
- `launcher.info {}` → installationId, profileId, sessionId, executable, installRoot, dataRoot, portable, instanceRoots, launcherState:"ready", backgroundStartup:false. Paths are effective absolute Launcher paths, never reconstructed by Manager.
- `instances.list {offset?,limit?,instanceRevision?}` → instances and warnings. Result payload definitions and method parameters are in requests.schema.json. Every instance has instanceId (native folder ID), uuid (logical metadata, may collide), physicalId (OS volume/file identity, opaque), canonicalPath, name, loaded, identityStatus, gamePhysicalId and modsPhysicalId. nativeRunning reports only the loaded model. nativeActivity is idle, launch_preparing, launch_active, deleting, unknown, or null for unloaded entries. launch_preparing includes queued launch/authentication; launch_active means the native LaunchTask is active, including downloads and prelaunch work. idle means no Launcher-known task, not proof that Java has stopped. gameState is always unknown and must never authorize a write. Shared game/mod directories are identity conflicts. Collisions/overlaps/aliases are reported. Unloaded collisions cannot be addressed by native ID.
- `mods.list {physicalId,offset?,limit?,instanceRevision?}` → items, total, nextOffset (integer or null), instanceRevision, revisionKind:"observation". limit 1–500, default 200; offset >=0. Inventory has no 100-item total cap. Pages use QDir::Name ordering. Every continuation must echo the first page's instanceRevision; mismatch returns STALE_INSTANCE and the client restarts. Instance pages sort by physicalId and use a separate listing observation token. A response exceeding the frame limit returns LIMIT_EXCEEDED; no truncated success. Unloaded entries are listing-only until a native inventory adapter can safely address them. Items expose fileName, enabled, size (decimal string), modifiedMs (decimal string), kind, linked, metadataState and metadata. Indexed metadata contains only name, provider, projectId, versionId, version and updateLocked, parsed with the native Packwiz reader. Missing/invalid indices are unindexed; duplicate associations are conflict with null metadata. An indexed record is a native metadata claim, not validation of JAR contents. Download URLs and credentials are omitted. Snapshot is filesystem observation, not a certified quiescent state. Do not use this token to authorize Apply. Same-length/timestamp-preserving edits can escape it; Prepare must hash bytes under the gate. No account, environment, command, raw configuration or arbitrary file content is exposed.
- Other methods return UNSUPPORTED_CAPABILITY, with no operation created and no files modified. `events.subscribe` is unavailable; reconnect and rescan read-only state.

Identity: UUID and folder name are never a lock key. Resolve directory handles to device/inode (Unix) or volume serial/file index (Windows), following symlinks/junctions. Missing/unverifiable identity fails closed. Roots are deduplicated by identity; aliases and ancestor/descendant roots generate warnings. Distinct directories with duplicate names/UUIDs stay distinct. IDs may change when directories are replaced, moved across volumes or restored; they are local, not sync IDs. Read discovery can race external changes and must never serve as mutation authorization. Inventory paths come exclusively from discovered native instances; linked files are observations only.

## Reserved operation contract (not enabled)
The following exact method names and fields are draft 1.0 extensions. Require capability true before calling; no fallback direct filesystem mutation.
- `providers.search {provider,query,minecraftVersions,loaders,offset}` and `providers.versions {provider,projectId,minecraftVersions,loaders}` → durable operation; completed result has native provider/project/version IDs, hashes, size, compatibility, dependency relations and download availability. Providers: modrinth, curseforge. Use ResourceAPI plus existing adapters/network stack; tokens remain native. Honor no-download responses and 429/Retry-After; no URL scraping or fabricated dependency resolution.
- `instances.create {idempotencyKey,name,minecraftVersion,loader?}` → operation; Loader uses native component UID/version. Launcher chooses validated native staging and destination. No caller paths.
- `plans.prepare {idempotencyKey,physicalId,instanceRevision,changes:[{action,provider?,projectId?,versionId?,inventoryId?}]}` → operation. Actions install, remove, enable, disable, component. Resolve exact artifacts/dependencies using native adapters, stage privately outside startup-cleaned temp directories, verify provider hashes and compute SHA-256, record baseline JAR/.index/config hashes, produce complete review result with warnings and unsupported actions. Reject unresolved required dependencies or filename/case collisions. Component edits require native PackProfile serializer. Cancellation before acquisition removes only that operation's staging.
- `plans.evaluate {physicalId,changes}` → evaluation only; never downloads/writes live files; not Apply authority.
- `transactions.apply {idempotencyKey,operationId,planDigest,instanceRevision}` → durable operation acceptance. operationId references prepared plan. planDigest is SHA-256 of Launcher-produced canonical plan bytes, including targets, content hashes, dependencies and baseline. Manager displays and echoes it; Launcher is the sole digest authority.
- `operations.get {operationId}` → durable state and terminal result/error. `operations.cancel {operationId}` → cancellationRequested, never a completion claim; repeated cancel is harmless. Critical apply/recovery sections are noncancellable.
- `events.subscribe {afterSequence?}` → sequence-ordered events with sessionId, operationId, state, progress. Reconnect via operations.get; cursor expiry returns EVENTS_GAP and requires rescan. Events are notifications, durable operation record is truth.
- `launch.request {idempotencyKey,physicalId}` → operation. Acquire gate before authentication/prelaunch, preserve existing account/Java/GPU behavior. INTERACTION_REQUIRED if dialog policy cannot be satisfied. Complete only at documented launch milestone (process-started), not queue acceptance; game exit is separate event.
- `recovery.list {}` → records including operationId, physicalId, phase, allowedActions. `recovery.run {idempotencyKey,operationId,action:"rollback"}` → operation; no generic filesystem recovery RPC. Resume is unsupported until proved safe.

requestId identifies one exchange. idempotencyKey (1–128 ASCII safe characters) deduplicates side effects across reconnect/restart within profile: persist key + canonical request hash + operationId before acceptance. Different body under same key returns IDEMPOTENCY_CONFLICT. Retain terminal records until an explicitly documented retention policy is agreed; never silently reuse a key. operationId is Launcher-generated UUID. instanceRevision is exact hash baseline under a quiescent gate for writes. planDigest binds the reviewed plan; neither is a requestId or idempotency key.

States: queued → resolving → downloading → prepared → acquiring → revalidating → backing_up → applying → verifying → completed. Alternate terminal states: cancelled, failed, rolled_back; recovery_required is nonterminal and blocks unsafe use. Cancellation is a request; terminal:false until durable conclusion. A prepared operation may wait for Apply; timeout/expiry policy remains unresolved and must be explicit before enabling it.

## Safety and recovery requirements
Acquire an OS-backed, per-physical-instance gate across profiles/processes, with overlapping game roots detected. Every relevant legacy writer, rename/delete, component edit, scan/index writer, save timer and launch preparation must participate. Wait for earlier writes/scans, flush settings/PackProfile, revalidate physical identity and exact baselines. isRunning() alone is insufficient. A durable active-launch marker must survive Launcher crash; unverified surviving Java blocks writes. Writable instances require explicit enrollment for exclusive use by gate-aware Launcher versions (user decision). Enrollment is itself unavailable until the gate/recovery path is complete. Unenrolled instances retain ordinary legacy behavior. Define supported local filesystems and crash durability before enabling Apply.
Backup all affected JAR, .index and config files in persistent private recovery storage. Flush backup bytes and durable journal before each live mutation; record phases and per-file intent/results. Use controlled serializers and same-directory replace where available; the sequence is recoverable, not a fully atomic multi-file filesystem transaction. Recovery validates journal/paths/hash preconditions, restores or quarantines safely, preserves data on rollback failure and blocks launch until verified. Recovery runs without Manager. Never clean recovery storage as temp; startup must find incomplete operations before scans/saves/launch.

## Errors and client behavior
Codes: INVALID_REQUEST, UNSUPPORTED_PROTOCOL, HANDSHAKE_REQUIRED, UNSUPPORTED_CAPABILITY, LIMIT_EXCEEDED, NOT_FOUND, IDENTITY_UNVERIFIABLE, IDENTITY_CONFLICT, BUSY, STALE_INSTANCE, STALE_PLAN, IDEMPOTENCY_CONFLICT, PROVIDER_RESTRICTED, RATE_LIMITED, DOWNLOAD_FAILED, INTEGRITY_FAILED, INTERACTION_REQUIRED, CANCELLED, RECOVERY_REQUIRED, RECOVERY_FAILED, EVENTS_GAP, IO_ERROR, INTERNAL_ERROR.
Validation/protocol/stale/digest errors are not retryable without correction/review. BUSY/RATE_LIMITED can retry only when marked retryable. Unknown errors fail closed. Reads may be retried after hello; side effects only with original idempotencyKey.
