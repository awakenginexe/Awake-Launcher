# Standalone native helper protocol 2.0

Contract for `awake-core-host.exe`, Windows x64, role `modpack-core`, implementation 0.2.0. Launcher protocol 1.0 and its endpoint remain unchanged. Manager 0.1 Modrinth requests retain their shapes. New functionality is negotiated with additive capabilities. Capability booleans describe availability. See core.schema.json for strict parameter/result definitions and core.examples.jsonl for mockable exchanges covering every method.

## Startup and transport
Package layout: `core-host/windows-x64/awake-core-host.exe`, sibling Qt Core/Network DLLs, qt.conf and required plugins. Tauri Rust resolves this trusted resource, uses CREATE_NO_WINDOW and `--profile <private absolute directory>`. The helper needs no Launcher installation, GUI or account. Use descriptor/hello readiness, not stdout EOF. Do not kill the helper on frontend timeout/disconnect/UI exit. It remains alive for active/prepared work and unresolved recovery. `core.shutdown` is refused until safe.

Descriptor: `<profile>/integration/core-v2/endpoint.json`. Pipe name `awake-core-v2-<session UUID>`. Verify pipe server PID and same-user SID, then protocol/role/profile/session; discovery files alone are not authentication. Server verifies local peer identity. Fixed local private profiles only; no remote clients. The profile coordinator lock prevents duplicate helpers. Independent profiles still share the canonical per-user physical ownership namespace. No caller may select its lock namespace.

Frames: big-endian uint32 byte length plus UTF-8 JSON object, 1â€“1,048,576 bytes. Eight clients, one request in flight per connection, no pipelining, 30-second idle timeout (suspended during active requests). Request `{protocol:{major:2,minor:0},requestId,method,params}`; response echoes protocol/requestId and exactly one of result/error. Unknown fields/types, unsafe identifiers and out-of-range values are rejected. Reconnect starts with hello; offers may include future versions alongside 2.0. No credentials, arbitrary path writes/deletes or command execution.

## Methods
All result shapes and optional fields are in the schema; unsupported methods return UNSUPPORTED_CAPABILITY without creating an operation.

| Method | Purpose |

| hello | Offer versions/client; receive role, core/storage versions, profile/session, capabilities and limits. |
| core.info / core.shutdown | Resolved profile/state; request safe shutdown. |
| catalog.versions | Minecraft and supported loader choices; Vanilla/Fabric/Forge/NeoForge/Quilt; exact version requirements validated. |
| workspaces.create / workspaces.list | Durable creation in helper-controlled storage; list enrolled Manager-owned physical workspaces. No existing-instance adoption. |

| providers.search / providers.versions | Modrinth or locally authorized CurseForge reads, filtered by Minecraft/loader, bounded paging. Public artifact URLs/hashes; no secrets. |

| transactions.apply | Apply only the exact operationId/planDigest/instanceRevision reviewed by the user. |
| mods.list / updates.check | Hash-aware installed inventory; compatible update candidates. Updates require a new reviewed plan. |
| operations.get / operations.list / operations.cancel / events.poll | Durable status, coalesced progress snapshots, cancellation acknowledgement and reconnect. |
| recovery.list / recovery.run | Inspect retained recovery and request verified rollback. No arbitrary filesystem recovery. |

Create produces native instance.cfg/mmc-pack.json plus a materialized `.minecraft/mods` tree. Name is display text; destination is backend chosen. The user must select Minecraft and loader versions. The helper does not launch Minecraft or authenticate accounts. Launcher adoption/sharing and native archive export remain unavailable; tracked config export is restricted as described below. The distributed helper has no CurseForge credential; credential-backed methods are unavailable until separately authorized local access is configured.

Prepare changes: install/replace use provider-scoped projectId/versionId (provider defaults to modrinth); remove/enable/disable use inventoryId from the current revision. Required dependencies appear in review and are integrity-checked. Optional/embedded dependencies are reported without silently downloading extra files; incompatible or unsatisfied required versions block preparation. This is declared metadata checking, not a complete runtime compatibility guarantee. Unknown files are never pruned automatically. No UI 100-item limit applies.

`updates.check` offers stable compatible versions published strictly after the installed version. A newer installed beta cannot be downgraded to an older release. If the installed version is absent from the provider's compatible history, no candidate is inferred. `providers.versions` is sorted by publication date, newest first. Manager selects explicit version IDs for each reviewed update; dependencies are resolved together. Plans allow 10,000 affected files, with at most 1,024 resolved projects. Provider JSON is bounded to 32 MiB, each artifact to 1 GiB. Downloads enforce declared size, SHA-512 and SHA-1. API calls are paced; 429 returns RATE_LIMITED rather than automatically retrying indefinitely.

Canonical policies live at `.awake-integration/policies.json`: installed project/version/artifact identity, pin and exclusion intent. Extended inventory reports `policy:{pinnedVersion:string|null,excluded:boolean}` and `nativeLock:boolean` (observed native lock OR persisted native lock). `updateLocked` remains their aggregate OR for compatibility; it never means pinned by itself. `metadataState` still controls whether installed metadata is verified. Inventory combines canonical policies with native Packwiz `x-prismlauncher-lock-update` using an OR rule; a native lock never clears a pin. A reviewed `action:"policy"` change sets `pinnedVersion` (the installed version or null) and `excluded`; it cannot clear a native lock. Upstream baseline reconciliation is unavailable. Verified inventory also checks the actual provider SHA-512 and native `.index` identity; modified files cannot be silently blessed by policy edits. Display titles are not extracted from JARs. CurseForge identity uses `curseforge:<projectId>` storage keys and SHA-1/native CurseForge metadata; Modrinth storage keys and responses remain unchanged. Managed override paths and imported hashes are also included in policies and instance revisions.

## Durable operations and review
requestId correlates one exchange. idempotencyKey deduplicates side effects across restart; reusing a key with a different method/body is IDEMPOTENCY_CONFLICT. operationId identifies the persisted work. planDigest binds exact targets/hashes/metadata/dependencies and the expected resulting inventory. instanceRevision is an exact content baseline, checked under the gate immediately before writes. None of these fields substitute for each other.

Submission result is `{operationId,state,terminal,replayed}`. Fresh accepted work is nonterminal, never completed merely because it was queued. Follow operations.get; after a lost reply resend the identical request/key. Apply references the prepared operation and adds an idempotent authorization to it. Extended `plans.get.files[]` includes `kind:mod|override|bookkeeping`; metadata/index/policy files are bookkeeping. These fields are omitted for legacy clients. The review plan is immutable and paged; fetch every page before confirmation. Prepared plans have no automatic expiry in this slice; explicitly cancel unused ones.

Unknown bytes/ownership, missing game evidence, unsupported record versions and unverifiable rollback retain evidence and fail closed. Multi-file replacement is recoverable, not globally atomic. A second writer cannot bypass the gate by selecting another registry/profile. Shared Launcher adoption is unavailable until all native writers/scans/saves/launch preparation honor the authority protocol.

The fixed authority namespace is the OS-resolved LocalAppData `AwakeSharedCore/authority-v1`, keyed by volume/file identity. Authority **kernel generation 2**, profile/operation storage version 1 and wire protocol 2.0 are separate version domains. Generation 1 experimental ownership and transaction format 1 are rejected without migration; retain their evidence and use their matching build for inspection. New transaction plans use format 2 and bind original file IDs as well as hashes. Originals displaced by guarded handle renames are retained under `.awake-integration/transactions/<operationId>`; partial incoming files are removed only when their recorded identity and staged-byte prefix can be verified. Unknown changes are preserved and require inspection. The executor never overwrites a newly occupied destination.

Startup rolls back interrupted mutation before advertising readiness, or verifies durable commit intent and completes it. Unresolved recovery keeps the helper alive and blocks shutdown. A partially initialized workspace before its creation manifest was published is retained for inspection; automatic cleanup/resume is unavailable. Prepared operations also keep the helper alive until applied or cancelled. An otherwise idle helper exits after 60 seconds without clients or work. Client/job termination is not cancellation.

Errors: INVALID_REQUEST, UNSUPPORTED_PROTOCOL, HANDSHAKE_REQUIRED, UNSUPPORTED_CAPABILITY, LIMIT_EXCEEDED, NOT_FOUND, NOT_ENROLLED, INCOMPATIBLE_OWNERSHIP, BUSY, STALE_INSTANCE, STALE_PLAN, IDEMPOTENCY_CONFLICT, DEPENDENCY_CONFLICT, POLICY_CONFLICT, PROVIDER_RESTRICTED, RATE_LIMITED, DOWNLOAD_FAILED, INTEGRITY_FAILED, CANCELLED, RECOVERY_REQUIRED, RECOVERY_FAILED, IO_ERROR, INTERNAL_ERROR. New errors include PROVIDER_UNAVAILABLE, INVALID_ARCHIVE and TRANSFER_DISCARDED. Each error has message and retryable. A retry never silently substitutes another version/plan.

## Manager 0.2 extensions

Capabilities: `loaders.forge.v1`, `loaders.neoforge.v1`, `loaders.quilt.v1`, `policies.v1`, `providers.curseforge.v1`, `imports.inspect`, `imports.prepare`, all four inbox transfer methods, `inbox.discard` and `inbox.discard.v1`. Query availability from hello; a loader capability does not assert compatibility with every Minecraft version. Forge/NeoForge use Prism metadata's exact Minecraft requirements; Quilt requires a supported intermediary. Native components use `net.minecraftforge`, `net.neoforged`, `org.quiltmc.quilt-loader`, and existing Fabric/intermediary UIDs. This creates recognizable instances, not an authentication or launch engine.

Upload sequence: `inbox.begin({idempotencyKey,purpose:"import",size,sha256})`, then `inbox.write({token,offset,bytesBase64})` in canonical base64 chunks of at most 262144 decoded bytes, then `inbox.commit({token})`. Sizes/offsets are decimal strings. Transfers are resumable; identical overlapping chunks replay, differing bytes conflict. A transfer is at most 1 GiB; at most 16 unfinished transfers and 4 GiB retained declarations. No complete archive belongs in an ordinary request frame. After staging or abandoning an import, call `inbox.discard({token})`; retrying discard returns `{token,discarded:true}`. A discarded key/token cannot be reused for upload. Discard never touches workspace files or prepared staging; changed discard intent is RECOVERY_REQUIRED.

`imports.inspect({token,format})`, with format `mrpack` or `curseforge`, returns Minecraft/loader selections, override paths/hashes/sizes, CurseForge project references, download count, and warnings. It does not apply changes. Create a workspace with those exact selections, or select an existing matching workspace. `imports.prepare({idempotencyKey,physicalId,instanceRevision,token,format,includeOptional?})` resolves/downloads into private staging and returns the ordinary accepted operation. Default includeOptional is false. Await prepared, fetch every plans.get page, review, then use the unchanged transactions.apply authorization. Creation is a separate durable operation; a failed import leaves that workspace intact.

Modrinth files are resolved by SHA-512, checked against compatible version metadata, and retain the hash-selected artifact, including secondary files. The install/replace change extension `artifactSha512` selects that exact Modrinth file. Required dependencies use provider metadata; unsupported direct hosts/manual artifacts return PROVIDER_RESTRICTED and never produce an applicable partial plan. Non-mod downloads currently require the Modrinth CDN. Required CurseForge files require API authorization; their downloads are never guessed from file IDs. Client overrides take precedence over common overrides. Existing unmanaged files and modified imported files cannot be replaced; conflict errors identify the path. A package cannot silently change workspace loader versions.

ZIP support is deliberately bounded: single-disk ZIP32, stored/deflate entries, no encryption/links/ZIP64, at most 10000 entries, 1 GiB archive/per entry, 2 GiB expanded, 200:1 per-entry ratio, 8 MiB manifests. Unsafe Windows names, traversal, aliases at the filesystem boundary, collisions, overlapping data and inconsistent headers are rejected. Server-only Modrinth entries are excluded. Unsupported states are errors, not successful imports.

Existing protocol 2.0 profiles without override policies retain their original revision calculation. New prepared override plans require this implementation or newer for recovery; do not downgrade helpers while they exist. Journal format 2, ownership generation 2 and storage version 1 remain distinct from the wire version.

The `manager.v0.2` handshake extension is explicit: add `extensions:["manager.v0.2"]` to hello params to enable the new capabilities and payload variants. Omitting it returns only the original Manager 0.1 capability keys, with inbox disabled, and core.info reports Vanilla/Fabric. Legacy clients receive UNSUPPORTED_CAPABILITY with an upgrade message for workspaces/results that require newer loader/provider types; those data are never returned in invalid legacy shapes. Existing Vanilla/Fabric Modrinth workflows remain usable against the unchanged 0.1 schema.

## Final integration contract additions

`x-methods` is the complete method table, including `imports.inspect`, `imports.prepare`, and `inbox.discard`. Their `capability` names equal the method name and their `extension` is `manager.v0.2`. `inbox.discard.v1` is a capability alias, not an RPC method. All method parameters/results remain defined in `$defs` and the request union.

When hello includes `extensions:["manager.v0.2"]`, the result explicitly echoes `extensions:["manager.v0.2"]`. An explicit empty offer returns `extensions:[]` and legacy capabilities. Unsupported, duplicate, non-array and malformed offers are INVALID_REQUEST; a failed first hello never authorizes further calls. Omitting the field omits it from the result, preserving strict Manager v0.1 schemas. Reconnects negotiate again. Check both accepted extension and capability flags. Old extension-aware clients must re-pin this schema before accepting the additive response fields.

`providers.project({provider,projectId})` returns `{project}` using the existing project shape. It requires the `providers.project` capability and extension. Compatibility arrays are empty because ID lookup does not establish version/loader compatibility; use providers.versions for that. CurseForge still requires separately approved native authorization and otherwise returns PROVIDER_UNAVAILABLE.

`outbox.configs.v1`, `outbox.list` and `outbox.read` are extended read capabilities. `outbox.list({physicalId,instanceRevision,offset?,limit?})` returns `{instanceRevision,files:[{path,size,sha256}],total,nextOffset}`. Paths are relative to `.minecraft` and include only policy-tracked `.minecraft/config/` overrides with extensions json/toml/cfg/conf/ini/properties/txt/yaml/yml, unchanged from their imported hash. It does not enumerate arbitrary workspace files. `outbox.read({physicalId,instanceRevision,path,offset,length})` returns `{path,instanceRevision,offset,size,bytesBase64,eof,sha256}`; offsets/sizes are decimal strings, length is 1..262144 decoded bytes, and each file is at most 8 MiB. Hashes cover the complete file. An offset equal to size returns an empty EOF chunk. Retain one revision across list/read pages; changed content is STALE_INSTANCE, changed imported hash is POLICY_CONFLICT, unsafe/untracked paths are NOT_FOUND, and unresolved recovery is RECOVERY_REQUIRED. Existing ownership, physical leases, private storage and reparse/alias checks apply. No writes, raw absolute paths, account files, logs, saves, untracked files, or changed configs are exposed. The reserved `{token,offset,length}` outbox request still returns UNSUPPORTED_CAPABILITY. No archive producer/token lifetime is introduced.

## Manager 0.2.1: dependency evidence and Connector imports (`manager.v0.2.1`)

Helper implementation 0.2.1 keeps wire protocol 2.0 and adds one further opt-in hello extension, `manager.v0.2.1`. It implies every `manager.v0.2` feature. Offer exactly one extension. A `manager.v0.2.1` offer is echoed as `extensions:["manager.v0.2.1"]` and adds two capability flags: `dependencies.resolutions.v1` and `loaders.connector.v1`. Clients that offer `manager.v0.2` or no extension get the earlier capability maps and payload shapes byte for byte. `error.details`, `plans.get.dependencyResolutions` and `mods.list.items[].loaderBridge` are removed for them, and a `dependencyResolutions` parameter from them fails with UNSUPPORTED_CAPABILITY. A helper older than 0.2.1 rejects the new offer with INVALID_REQUEST. Reconnect and offer `manager.v0.2`.

### Provider claims and loader evidence

Provider dependency records are claims. Exact `version_id` pins usually record the library build current at upload time. Mods enforce the ranges in their own loader metadata. Plan preparation therefore no longer stops at the first dependency mismatch. It checks the whole resulting graph and collects every problem. For each one it reads bounded, named entries from the verified JARs: `META-INF/mods.toml`, `META-INF/neoforge.mods.toml`, `fabric.mod.json`, `quilt.mod.json`, and `MANIFEST.MF` for `${file.jarVersion}`. Nothing is extracted or executed. Ranges are evaluated with Maven semantics for Forge/NeoForge and SemVer predicates for Fabric/Quilt. When anything remains, the operation fails with DEPENDENCY_CONFLICT before any artifact is staged. Details appear only in a direct error reply or `operations.get` (never in `operations.list`/`events.poll` pages), capped at 64 conflicts, 32 requesters each and 192 KiB with `truncated:true`. The message names projects by title, and `error.details.conflicts[]` (`$defs/dependencyConflict`) lists:

- `kind`: `version_pin` (another version of a project the plan already selects is pinned), `missing_dependency` (no version exists for this Minecraft version and loader), `incompatible` or `loader_bridge`.
- the dependency's `title`, the `selected` version and file, and `candidates` (the selected version plus compatible pinned versions, unless the package selected the dependency explicitly).
- every requesting mod with title, version, file, the requested version number and `evidence`. Evidence is `satisfied`, `violated`, `not_declared` or `unknown`, plus the declared range, mandatory flag, mod ID and the selected mod version.
- `resolutions`: the reviewed choices the helper will accept.

`use_version` is offered for a `version_pin` unless some requester's metadata rejects the selected version. `proceed_without` is offered for a `missing_dependency` only when no requester declares the dependency in its loader metadata. A declared or unknown requirement is never skipped. `incompatible` and `loader_bridge` conflicts have no resolution.

### Reviewed resolutions

`plans.prepare` and `imports.prepare` accept `dependencyResolutions:[{projectId, provider?, versionId}]`, at most one per dependency project. `versionId` is the version to keep or choose; `null` means proceed without the project. The helper re-reads the evidence and refuses any resolution it contradicts. A resolution can never name a version other than the one a package file explicitly selects. Accepted resolutions are bound into the reviewed plan (`plans.get.dependencyResolutions`, covered by `planDigest`) and listed as `Reviewed:` warnings. They are stored with the requesting mod's installed version, so later plans do not ask again until either that mod or the dependency changes version.

An installed, unlocked dependency that no other change in the plan selects follows a requester's pin only to a newer-published build, and the plan says so in a warning. A pin to an older build, or to a different version of a dependency the plan selects explicitly, is always a `version_pin` conflict. Libraries are never downgraded or replaced silently.

### Combined mod and datapack projects

The shared Modrinth parser classifies any project whose loaders include `datapack` as a datapack. The helper accepts such a project as a mod only when the provider reports `project_type:"mod"` together with a real mod loader. The installed version must still list the workspace loader and ship a `.jar` primary file. Datapack-only versions and datapack-only projects are still refused.

### Sinytra Connector (`loaders.connector.v1`)

In a Forge or NeoForge workspace, `imports.prepare` admits a Modrinth file whose version is tagged `fabric` but not with the workspace loader under three conditions: the package identifies that exact file by SHA-512, the Minecraft version matches, and the resulting workspace enables Sinytra Connector (`u58R1TMW`). Its Fabric API (`P7dR8mSH`) requirement is satisfied by Forgified Fabric API (`Aqlf1Shp`), which Connector itself requires. Its other requirements must already be present; none are installed automatically. `plans.prepare` never bridges a file. The mod is listed with `loaderBridge:"sinytra-connector"`. Removing or disabling Connector while a bridged mod is enabled is a `loader_bridge` conflict. Whether a given Fabric mod actually works under Connector is not verified.
